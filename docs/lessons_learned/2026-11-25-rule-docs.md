# Rule documentation

Added one document per analyzer rule in `docs/rules/` (`GQ0001.md`–`GQ0004.md`) plus `docs/rules/INDEX.md`, formatted like the lessons-learned index.

## Notes for next session

- Source of truth for rejected/accepted cases is the analyzer test projects (`*AnalyzerTests.cs`): every sample in the docs is taken from a test, and the messages in the docs match the descriptors in the analyzers. When a rule changes, update the doc together with the tests.
- Rule metadata (category `Naming`, severity `Warning`, enabled by default) comes from the defaults of `RuleHelper.Create`; none of the analyzers override them.
- The four rules overlap on purpose: GQ0001/GQ0003 cover names, GQ0002/GQ0004 cover built-in aliases, and the `using` variants (GQ0003/GQ0004) are the only ones that look inside using directives. Each doc's "Not reported" section points to the rule that covers the excluded case, so keep those cross-links when adding a rule.
- An "accepted" sample for one rule can still trigger another (e.g. `object` in a GQ0001 sample triggers GQ0002). Either make samples clean for all rules or say which rule still fires.
